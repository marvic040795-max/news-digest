# Новостной дайджест

Раз в день (или по кнопке) ищет новости по твоим темам через Claude API
с web search, фильтрует шум и присылает сводку в Telegram.

## Настройка (один раз)

### 1. Создать репозиторий на GitHub
Залей эту папку в новый **приватный** репозиторий (данные внутри —
только твои темы и ссылки, но приватность лишней не будет).

### 2. Создать Telegram-бота
1. Напиши в Telegram боту **@BotFather** → `/newbot` → задай имя.
2. Он даст токен вида `123456:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`
   — это `TELEGRAM_BOT_TOKEN`.
3. Напиши своему новому боту любое сообщение (например "старт"),
   иначе он не сможет писать тебе первым.
4. Узнать свой `chat_id`: напиши боту **@userinfobot** — он пришлёт
   твой numeric id. Это `TELEGRAM_CHAT_ID`.

### 3. Добавить секреты в репозиторий
В репозитории: **Settings → Secrets and variables → Actions →
New repository secret**. Добавить три:
- `ANTHROPIC_API_KEY` — твой ключ с console.anthropic.com
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

### 4. Проверить вручную
Вкладка **Actions** → workflow "Новостной дайджест" →
**Run workflow** (кнопка справа). Поля в окне запуска:

- **only_topic** — id одной темы из `config/topics.json` (например
  `exmo_funds_recovery`). Опросит только её, копейки. Лучший способ
  проверить новую или переписанную тему.
- **force** — опросить ВСЕ темы мимо расписания. Дорого, нужна редко.
- оба поля пустые — отработают только темы, у которых подошёл срок
  (если сроков нет, запуск ничего не тратит).

Если сообщение не пришло — открой лог запуска, шаг "Запустить дайджест":
по каждой теме там напечатано, сколько было поисков и токенов.
При ошибке ключа/баланса API бот сам напишет предупреждение в Telegram.

## Как добавлять/менять темы

Открой `config/topics.json`, добавь объект по образцу:

```json
{
  "id": "уникальный_id_латиницей",
  "name": "Название темы",
  "what_matters": "Что именно считать важным событием",
  "entities": "Конкретные источники/органы/сервисы, по которым реально идут новости",
  "ignore": "Что явно считать шумом",
  "frequency": "weekly"
}
```

`frequency` — `weekly` (по умолчанию) или `monthly` (редкие события).
Значение `daily` скрипт понимает, но **не используй его без нужды**:
каждая такая тема стоит денег каждый день.

Необязательное поле `"max_searches": 3` — поднять число поисков для
одной важной темы (по умолчанию 2).

Чем точнее `what_matters` / `entities` / `ignore` — тем чище будет
результат. Общее название темы без уточнений работать не будет —
поиск будет находить общие статьи-гайды вместо новостей.

## Расписание

Запуск — по понедельникам, 07:00 по Новосибирску (правится в
`.github/workflows/news-digest.yml`, строка `cron:`). В понедельник
скрипт сам смотрит, у каких тем подошёл срок (`weekly` — через 7 дней
после прошлого опроса, `monthly` — через 30), и опрашивает только их.
[crontab.guru](https://crontab.guru/) — если нужно поменять время.

## Про деньги

Из чего складывается цена одной темы:

1. **Поиск** — $10 за 1000, то есть $0.01 за каждый поиск.
2. **Токены** — и это главная часть, которую легко недооценить: страницы
   из поиска засчитываются как входные токены, на один запрос их уходит
   порядка 20–40K. Цена токенов зависит от модели. По сторонним обзорам,
   у Haiku 5.5 это $0.10 за 1M на входе и $0.50 на выходе, но запрос
   дороже 100K токенов тарифицируется в 5 раз выше. Сверяй с консолью.

Отсюда настройки по умолчанию: **2 поиска на тему** (так запрос
остаётся далеко от порога 100K), темы раз в неделю и раз в месяц.
Ориентир: ≈ $0.02–0.03 за тему → примерно 66 опросов в месяц
(14 недельных × 4.3 + 6 месячных) → **$1.5–3 в месяц**.

Предохранители в скрипте:
- состояние сохраняется после каждой оплаченной темы — упавший прогон
  не заставит платить за то же второй раз;
- потолок `RUN_SEARCH_BUDGET` (50 поисков за прогон);
- лимит `timeout-minutes` и запрет параллельных прогонов в workflow;
- в Telegram после дайджеста приходит строка "Прогон: тем N, поисков M,
  ≈$X" — расход виден сразу, без захода в консоль.

Реальный расход: https://console.anthropic.com/settings/usage — первые
две-три недели лучше сверять с ним оценку из лога.

## Состояние (data/seen_urls.json)

Файл хранит уже присланные ссылки по каждой теме, чтобы не
повторяться. Обновляется и коммитится в репозиторий автоматически
после каждого прогона — руками трогать не нужно.
